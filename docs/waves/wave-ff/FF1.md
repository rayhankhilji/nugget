## Your package
**FF1: your data is safe: backup, restore, export, crash safety.** Nugget keeps a user's whole digital life in one encrypted store. v1 needs proof that it survives crashes and power loss, that it can be backed up and restored, and that the user can take everything out in open formats.
- **Crash safety, proven.** A test harness that kills `nuggetd` with SIGKILL (and the Windows equivalent) at random points during ingest, re-embedding, knowledge extraction and vault writes, hundreds of times in CI, then checks `PRAGMA integrity_check`, the audit hash chain, the FTS and vector indexes agreeing with the items table, and that indexing resumes without duplicates or loss. Fix anything it finds.
- **Backup and restore.** An encrypted, versioned backup of the store and settings (online, consistent: SQLite backup API or `VACUUM INTO` on the SQLCipher DB, never a file copy of a live DB), to a folder the user picks, on a schedule, with retention; restore into a fresh home, verified, including onto another OS. Keys: document and implement how the backup is unlocked (the store key, exported under a passphrase the user sets), and what happens if the key is lost (say it plainly).
- **Export.** One command and one button: everything as open formats (the Markdown vault, items as JSON Lines with their source metadata, the knowledge graph as JSON, the audit log and egress ledger as CSV), streamed so 100k items works on 16 GB.
- **Recovery.** Detect a corrupted DB at start, refuse to write to it, offer restore from the last backup, and never lose the original file.
- **Desktop:** a Backup and export section in Settings (find the settings page; EE6 is polishing styles, so add your section with existing components), strings in all 8 catalogs plus review lists, an e2e scenario that backs up, wipes, restores and searches.
